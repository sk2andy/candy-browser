# Smoother browsing, steadier pages

Candy Browser 0.39 improves Gecko scrolling and edge-to-edge layouts, keeps website inputs
visible when typing, and restores reliable download and app-link handling.

![Candy's floating address bar with a website header below the Android status bar](https://raw.githubusercontent.com/sk2andy/candy-browser/v0.39/docs/screenshots/candy-frosted-address-bar.png)

## Edge-to-edge with less repair work

- Safe-area protection now uses persistent CSS instead of repeatedly measuring headers during
  normal scrolling. Page backgrounds still extend behind the system bars.
- Google's expanded search field receives its safe-area rule before focus changes its layout,
  reducing the late correction seen when opening search.
- Amazon.de product navigation stays protected when a scrolling state activates its fixed header,
  including rules from later-loaded stylesheets.
- Reddit receives scoped component rules for its headers and page flow. Subreddit banners start
  below the header and scroll away normally without adding the same inset twice.
- Developer settings retain safe-area controls and the existing emergency fallback for layouts
  that need it. Site-specific layout variants can still require further adjustments.

Learn more in [Browsing and gestures](https://github.com/sk2andy/candy-browser/blob/v0.39/docs/browsing/README.md#topic-lookup).

## Keep typing and website themes in sync

- Gecko accounts for the on-screen keyboard and keeps focused website inputs in the available
  viewport.
- Website dark-mode preference follows the effective Android app appearance, including switching
  back to **System** after a light or dark override.

Learn more in [Appearance settings](https://github.com/sk2andy/candy-browser/blob/v0.39/docs/browsing/appearance-and-settings.md#invariants).

## Downloads that follow your choice

- Website and context-menu downloads respect the selected built-in or external download manager,
  or the **Ask every time** choice.
- Active built-in downloads can be cancelled. Gecko transfers also support **Pause** and **Resume**
  while Candy's process and the original response remain alive.

> Gecko pause/resume is not restart recovery. A server timeout can still end a paused transfer;
> Android DownloadManager and page-generated blob downloads support cancellation only.

Learn more in [Downloads](https://github.com/sk2andy/candy-browser/blob/v0.39/docs/browsing/downloads.md#behavior).

## Small changes that save a tap

- Enable **Undo closed tab** in Tabs & gestures for a three-second chance to restore the most
  recently closed tab.
- Open the available version's **Release notes** directly from the update dialog before choosing
  whether to download it.
- Google Play links target the Play Store when available, with a browser fallback when it is not.
  External app handoffs no longer leave Candy stuck in a task or navigation loop.

Learn more in [Tabs and profiles](https://github.com/sk2andy/candy-browser/blob/v0.39/docs/tabs-and-profiles/README.md) and [Release notes](https://github.com/sk2andy/candy-browser/blob/v0.39/docs/releases/README.md#release-contract).

## Private by design

These changes preserve private-tab boundaries. Tab-close recovery stays in memory, and private
closed-tab URLs are never written to storage.
