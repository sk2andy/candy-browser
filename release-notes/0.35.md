# Personal profiles and smoother browsing

Candy Browser 0.35 gives every local profile its own look and makes everyday navigation more
reliable across websites, Android apps, downloads, and desktop-mode pages.

![Candy Browser's tab overview](https://raw.githubusercontent.com/sk2andy/candy-browser/v0.35/docs/screenshots/candy-tabs.png)

## Make each profile yours

- Give every local profile separate wallpapers for the new-tab page and tab switcher. Import an
  image with Android's document picker, then adjust its crop and zoom. Implements
  [#45](https://github.com/sk2andy/candy-browser/issues/45).
- Optionally open a fresh home page whenever Candy starts, without discarding restored tabs.
  Implements [#77](https://github.com/sk2andy/candy-browser/issues/77).
- Close every unpinned tab in the active profile from the tab-switcher overflow menu. Pinned tabs
  stay open. Implements [#41](https://github.com/sk2andy/candy-browser/issues/41).

Learn more in [Tabs and profiles](https://github.com/sk2andy/candy-browser/blob/v0.35/docs/tabs-and-profiles/README.md#topic-lookup)
and [Appearance settings](https://github.com/sk2andy/candy-browser/blob/v0.35/docs/browsing/appearance-and-settings.md#choices).

## Better website and Android integration

- Desktop view now keeps a consistent desktop identity across redirects, Back, Forward, and
  repeated navigation, with a wider layout viewport for better compatibility. Fixes
  [#69](https://github.com/sk2andy/candy-browser/issues/69) and
  [#74](https://github.com/sk2andy/candy-browser/issues/74).
- Supported web links can open directly in their installed Android app, while unavailable or
  ambiguous links stay safely inside Candy. External-link previews also become interactive sooner
  during cold starts. Fixes [#63](https://github.com/sk2andy/candy-browser/issues/63).
- HTTP Basic authentication now uses a focused, transient credential prompt and clearly warns when
  a site uses unencrypted HTTP. Fixes [#78](https://github.com/sk2andy/candy-browser/issues/78).
- Candy now includes the Android browser configuration required for WebAuthn/passkey providers.
  Provider allowlisting is still required before end-to-end passkey support can be considered
  complete. Tracks [#70](https://github.com/sk2andy/candy-browser/issues/70).

Learn more in [Runtime and navigation](https://github.com/sk2andy/candy-browser/blob/v0.35/docs/browsing/runtime-and-navigation.md#navigation-paths).

## Downloads and translation

- APK links and their authorized redirects now enter the download flow instead of opening a blank
  page. Renderable `.txt` and `.json` links gain an explicit **Download link** action in Link Peek.
  Fixes [#65](https://github.com/sk2andy/candy-browser/issues/65).
- Download Navi joins 1DM and ADM as a verified external download manager, with automatic fallback
  to Candy's built-in downloader. Implements
  [#76](https://github.com/sk2andy/candy-browser/issues/76).
- Page translation now uses Yandex as its compatibility-oriented default and invalid-value fallback,
  while Google, Yandex, and Kagi remain selectable providers. Fixes
  [#67](https://github.com/sk2andy/candy-browser/issues/67).

Learn more in [Address actions](https://github.com/sk2andy/candy-browser/blob/v0.35/docs/browsing/address-actions-and-ui.md#gestures-and-actions).

## More control and polish

- A new search setting can hide saved-history rows, automatic Candy Recall matches, and
  history-derived domain completion without deleting history. Open tabs, favorites, and explicit
  `>recall` searches remain available, and Google joins the selectable remote suggestion providers.
  Implements
  [#64](https://github.com/sk2andy/candy-browser/issues/64).
- Strict per-site popup blocking can reject every popup for a domain, independent of normal filter
  rules. Implements [#66](https://github.com/sk2andy/candy-browser/issues/66).
- CAPTCHA compatibility now offers an explicit, host-scoped cookie exception when strict blocking
  prevents a recognized challenge from working. Fixes
  [#68](https://github.com/sk2andy/candy-browser/issues/68).
- Frosted tab overviews now keep profile and action controls clear of display cutouts and navigation
  bars in both gesture and three-button navigation. Fixes
  [#56](https://github.com/sk2andy/candy-browser/issues/56) and
  [#79](https://github.com/sk2andy/candy-browser/issues/79).

Learn more in [Blocking and Candy Rules](https://github.com/sk2andy/candy-browser/blob/v0.35/docs/privacy-protection/blocking-and-rules.md#blocking-pipeline)
and [History](https://github.com/sk2andy/candy-browser/blob/v0.35/docs/browsing/history.md).

## Private by design

Private tabs remain memory-only. Popup and CAPTCHA compatibility choices stay temporary in private
tabs, private input never triggers remote suggestions, and profile wallpapers are neither shown in
private tabs nor synchronized to other devices.
