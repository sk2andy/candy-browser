# Candy Stacks and smarter link handling

Candy Browser 0.36 makes busy tab sets easier to manage and improves handoffs between web pages,
Android share sheets, installed apps, and Site Capsules.

![Candy Browser's tab overview](https://raw.githubusercontent.com/sk2andy/candy-browser/v0.36/docs/screenshots/candy-tabs.png)

## Group related tabs with Candy Stacks

- Create named and colored stacks from compatible tabs, collapse them into a layered card in
  Coverflow or Grid, and reopen them in a focused folder.
- Choose the collapsed preview tab and the folder's Coverflow, Grid, or List layout independently.
  Closing, snoozing, moving, or repinning a member safely reconciles its stack.
- Regular stacks persist with their profile. Private stack data remains memory-only. Implements
  [#53](https://github.com/sk2andy/candy-browser/issues/53),
  [#94](https://github.com/sk2andy/candy-browser/issues/94),
  [#95](https://github.com/sk2andy/candy-browser/issues/95), and
  [#96](https://github.com/sk2andy/candy-browser/issues/96).

Learn more in [Tabs and profiles](https://github.com/sk2andy/candy-browser/blob/v0.36/docs/tabs-and-profiles/README.md#topic-lookup).

## Move links where you want them

- Share a complete HTTP or HTTPS link from another Android app to Candy. Shared prose, malformed
  values, unsupported schemes, and multi-item payloads do not start navigation. Fixes
  [#84](https://github.com/sk2andy/candy-browser/issues/84).
- Choose what a long press on a page link does: open Link Peek, copy the link, open it in a background
  or private tab, or share it. This advances
  [#33](https://github.com/sk2andy/candy-browser/issues/33); its tap-to-popup and reading-list ideas
  remain open.
- Incoming links and permitted redirect chains can now open their verified associated Android app.
  If no unambiguous non-browser handler is available, the web destination stays in Candy. Fixes
  [#101](https://github.com/sk2andy/candy-browser/issues/101).

Learn more in [Address actions](https://github.com/sk2andy/candy-browser/blob/v0.36/docs/browsing/address-actions-and-ui.md#gestures-and-actions)
and [Runtime and navigation](https://github.com/sk2andy/candy-browser/blob/v0.36/docs/browsing/runtime-and-navigation.md#navigation-paths).

## Personalize Site Capsules and keep pages readable

- Give each Site Capsule its own emoji and accessible icon-tile color. The editor restores the
  choices, previews them, and updates the Android launcher shortcut without changing page or
  wallpaper colors. Implements [#93](https://github.com/sk2andy/candy-browser/issues/93).
- Transparent website canvases now remain owned by WebView instead of receiving a separate Candy
  background. This preserves author-defined foreground and canvas contrast across light, dark, and
  forced-dark configurations. Fixes [#100](https://github.com/sk2andy/candy-browser/issues/100).

Learn more in [Site Capsule lifecycle](https://github.com/sk2andy/candy-browser/blob/v0.36/docs/site-capsules/lifecycle-and-shortcuts.md#lifecycle-lookup)
and [Appearance settings](https://github.com/sk2andy/candy-browser/blob/v0.36/docs/browsing/appearance-and-settings.md#invariants).

## Private by design

Private stack metadata remains memory-only. Opening a long-pressed link privately falls back to
Link Peek when the active profile cannot create private tabs. External app handoffs require a
verified, unambiguous non-browser default; otherwise Candy keeps the web fallback.
