# More control over every handoff

Candy Browser 0.40 gives you a choice before links leave the browser, protects local profiles with
biometrics, and makes everyday navigation controls more adaptable and dependable.

![Candy's profile creator with isolated storage and a personal icon](https://raw.githubusercontent.com/sk2andy/candy-browser/v0.40/docs/screenshots/candy-profile-creation.png)

## Decide when another app opens

- **Open links in apps** now offers **Automatically**—the existing default—or **Always ask** in
  Browser settings.
- **Always ask** checks that a direct app is available, names the destination, and waits for explicit
  confirmation. Ordinary web links without an app continue in Candy without an unnecessary prompt.
- App links opened by `target=_blank` or `window.open` now follow the same safe handoff policy as
  links in the current page.
- Redirect handoffs are stopped before the external app opens. Returning to Candy keeps the original
  page instead of showing or retaining an intermediate `302 Moved` page.

Learn more in [Runtime and navigation](https://github.com/sk2andy/candy-browser/blob/v0.40/docs/browsing/runtime-and-navigation.md#navigation-paths).

## Protect a local profile

- Choose biometric protection and either wallpaper while creating a profile. Candy completes selected
  wallpaper editors first, then enables the drafted protection so setup is not interrupted by a lock.
- Long-press a local profile to enable strong-biometric protection and choose whether it locks
  immediately in the background or after a 1–1,440 minute cooldown.
- Locked profiles shield their page, detach browser content, pause media, and hide their History and
  Snooze entries until you unlock them.
- Protected content is hidden from Android Recents previews. Unlock state remains only in process
  memory, so protected profiles start locked after a fresh launch.

> Profile protection is an access lock. It does not add separate file encryption at rest.

Learn more in [Tabs and profiles](https://github.com/sk2andy/candy-browser/blob/v0.40/docs/tabs-and-profiles/README.md#topic-lookup).

## Put controls where they work for you

- Choose which actions appear in the tab menu, tab-switcher menu, both menus, or neither. Shared
  menu choices now stay consistent across Android and iOS where the underlying action is available.
- The tab switcher's overflow menu can close every unpinned tab in the active profile and now exposes
  Candy Stack actions more consistently.
- Pull down from the top of a visible page to refresh. The gesture stays out of blank, obscured,
  offline-game, and non-top-of-page states.
- Candy can automatically park the address bar on the right when a focused website editor would be
  covered, then leave it parked until you restore it.

Learn more in [Address actions and UI](https://github.com/sk2andy/candy-browser/blob/v0.40/docs/browsing/address-actions-and-ui.md#configurable-menu-actions).

## Smoother pages and cleaner builds

- Gecko respects pages that deliberately opt into `viewport-fit=cover`, while Google menus and the
  refresh indicator stay below status bars and display cutouts.
- Focused website editors are reprobed during keyboard and layout motion, improving address-bar
  parking on dynamic pages.
- Committed browser navigations are recorded more reliably in History.
- Firefox extension settings and other add-on chrome open on their intended Candy surfaces.
- The System WebView build no longer packages Gecko binaries, reducing unnecessary payload.

## Private by design

Private tabs remain memory-only. External-app prompts and redirect recovery are bound to the current
tab or transient preview, and profile unlock state is never persisted.
