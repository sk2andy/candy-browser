# More control over video, safer everyday browsing

Candy Browser 0.45.0 brings Candy Player controls and a dedicated Player settings page,
HTTPS-only protection, and fixes for navigation, dark appearance, and first-run onboarding.

## Make Candy Player your own

- Open **Settings → Player** to choose video autoplay behavior and Candy Player mode in one place.
  The experimental player offers inline, fullscreen, and automatic presentation for supported
  top-frame HTML videos in GeckoView.
- Use Candy's play/pause, seek, time, and fullscreen controls directly over the video. Tap the
  video to show or hide controls; double-tap the left or right half to seek.
- Set backward and forward double-tap distances independently: **5, 10, 15, 20, 30, or 60 seconds**.
  Each direction defaults to 10 seconds. Discrete sliders show the selected duration and give
  haptic feedback between stops when Android feedback is enabled.
- Fullscreen video fills the available viewport more reliably. Returning from fullscreen or
  Android picture-in-picture restores the page layout and its normal status-bar spacing.

> Candy Player remains experimental. Cross-origin iframe, canvas, and unsupported DRM players
> are outside its supported path; Android picture-in-picture still requires active playback.

Learn more about [video and player behavior](https://github.com/sk2andy/candy-browser/blob/v0.45.0/docs/browsing/runtime-and-navigation.md#web-media-fullscreen-and-picture-in-picture).

## Prefer encrypted connections

GeckoView now defaults to **HTTPS-only protection for all tabs**. In **Protection & Data**, choose
all tabs, private tabs only, or off. When a site cannot complete the HTTPS upgrade, a local warning
lets you go back, retry HTTPS, or explicitly allow HTTP for that site session.

Certificate errors do not offer the HTTP exception. System WebView does not support this setting,
and Gecko retains its own exemptions for local and other trusted destinations.

Learn more about [HTTPS-only protection](https://github.com/sk2andy/candy-browser/blob/v0.45.0/docs/browsing/platform-engines.md#https-only).

## Follow links and go back reliably

- Back from the first website in a Gecko tab follows Candy's normal tab and Android Back behavior
  instead of navigating to an internal startup page.
- Website popups preserve their original navigation, including form submissions and opener context.
- Search-result links continue into Candy when no matching external app is available, even if the
  search page updates its URL while Candy checks for installed apps.
- Android's edge Back gesture no longer opens Link Peek by accident. Intentional link long presses
  still open the preview.
- Gecko engine pages such as `about:config` can be opened from the address bar. Availability depends
  on the bundled engine; System WebView continues to search this input.

![An intentional link long press opens Candy's Link Peek preview above the current page](https://raw.githubusercontent.com/sk2andy/candy-browser/v0.45.0/docs/screenshots/candy-link-peek.png)

Learn more about [navigation and app links](https://github.com/sk2andy/candy-browser/blob/v0.45.0/docs/browsing/runtime-and-navigation.md#navigation-paths) and [Link Peek](https://github.com/sk2andy/candy-browser/blob/v0.45.0/docs/browsing/address-actions-and-ui.md#gestures-and-actions).

## Keep dark browsing consistent

Dark start-page and address-editor surfaces now use suitable dark colors. Websites receive the
same effective light or dark preference as Candy, including when following the Android system
setting. Selecting a tab while editing the address also restores the correct Gecko page surface.
The compact address pill stays clearer of bottom-edge page controls.

Learn more about [appearance behavior](https://github.com/sk2andy/candy-browser/blob/v0.45.0/docs/browsing/appearance-and-settings.md#invariants).

## A clean first start

New installations show **onboarding only**. Finishing or skipping the tutorial does not queue the
bundled changelog, and restarting during onboarding keeps the tutorial active. Existing users
continue to see release notes once after an app update.

Learn more about [onboarding and release notes](https://github.com/sk2andy/candy-browser/blob/v0.45.0/docs/releases/README.md#release-contract).

## Better bug reports, under your control

Optional **App logging** in Developer options records bounded local app events and sanitized crash
stacks. Reproduce a problem, then export the logs through Android's document picker to attach them
to a report. Logging is off by default, uploads nothing automatically, and pauses while private
tabs are open. Switching it off deletes local captures; copies you already exported remain yours.

Learn more about [logging and its privacy limits](https://github.com/sk2andy/candy-browser/blob/v0.45.0/docs/browsing/app-logging.md#privacy-and-storage-contract).
